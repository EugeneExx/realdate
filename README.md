# REALDATE

Адаптивная платформа для организации быстрых свиданий вживую. В проекте есть пользовательский кабинет, панель организатора, запись с учётом квот по полу, проведение мероприятия, закрытое голосование и выдача контактов только при взаимной симпатии.

## Что реализовано

- вход и регистрация по номеру телефона с одноразовым кодом;
- профиль: имя, пол, обязательная дата рождения с автоматическим расчётом возраста, фото, описание, Telegram, WhatsApp и MAX;
- каталог предстоящих мероприятий и история пользователя;
- квоты мест отдельно для мужчин и женщин;
- возрастной диапазон мероприятия носит рекомендательный характер; решение о допуске принимает администратор;
- обязательные согласия на обработку персональных данных и полную предоплату;
- админ-панель: создание и удаление события, возрастной диапазон, участники, оплата, подтверждение записи;
- статусы `registration → live → finished`, случайные номера внутри каждого пола;
- симпатии во время события и контакты только при взаимном выборе;
- уведомления и статистика по заявкам, подтверждениям, выручке и симпатиям;
- responsive UI: desktop/sidebar, tablet grids, mobile bottom navigation and compact tables.

## Стек

- React 19, TypeScript, Vite, React Router, Lucide, date-fns;
- FastAPI, SQLAlchemy Async, JWT, Pydantic;
- PostgreSQL 16 в Docker; SQLite используется только как zero-config fallback локального API;
- Docker Compose для воспроизводимого запуска.

## Быстрый запуск

```bash
docker compose up --build
```

Сайт: `http://localhost:5173`
API/Swagger: `http://localhost:8000/docs`

В dev-режиме код подтверждения — `1111`. Администраторы входят по номерам из `ADMIN_PHONES`, разделённым запятыми; `ADMIN_PHONE` сохранён для обратной совместимости. Перед публикацией обязательно задайте собственный `JWT_SECRET` и подключите реальный OTP-провайдер.

## Запуск без Docker

Backend:

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Frontend:

```bash
cd frontend
pnpm install
pnpm dev
```

## Production-рекомендации

В production используется только официальный Telegram Gateway. Для дальнейшего масштабирования можно вынести OTP и rate limiting в Redis, хранить фотографии в S3-совместимом объектном хранилище, добавить Alembic-миграции и фоновые задачи через Celery/Arq. Платёжный статус сейчас отмечает администратор; следующим шагом можно подключить ЮKassa с webhook-подтверждением.

152-ФЗ требует не только чекбокса: до запуска нужно подготовить тексты согласия и политики под фактического оператора данных, определить сроки хранения и разместить реквизиты оператора.

## Подготовка к проверке ЮKassa

Сайт содержит публичную витрину мероприятий и страницы, доступные без авторизации:

- `/offer` — публичная оферта;
- `/privacy` — политика конфиденциальности;
- `/personal-data-consent` — согласие на обработку персональных данных;
- `/payment-and-refund` — порядок оплаты и возврата;
- `/contacts` — контакты и реквизиты самозанятого.

Перед production-сборкой заполните в `.env` публичные реквизиты:

```env
LEGAL_NAME=Фамилия Имя Отчество
LEGAL_INN=000000000000
LEGAL_ADDRESS=Приморский край, г. Владивосток
SUPPORT_PHONE=+79990800137
SUPPORT_EMAIL=hello@example.ru
SUPPORT_TELEGRAM=katy_sha_00
DOCUMENTS_EFFECTIVE_DATE=15 июля 2026 года
```

Эти значения встраиваются во frontend на этапе Docker-сборки. После изменения
реквизитов пересоберите контейнер `web`.

Публичная афиша получает только активные мероприятия через `/api/public/events`.
Эндпоинт не возвращает профили, контакты, регистрации, симпатии и ответы квиза.
Перед отправкой заявки в ЮKassa удалите либо завершите тестовые мероприятия и
проверьте, что в афише остались только реальные встречи с актуальными ценами.

Для самозанятого сервис «Чеки от ЮKassa» не используется. После каждого
успешного платежа доход и чек необходимо регистрировать в «Мой налог».
